# DESIGN.md — Архитектурные решения Country Search

## 1. Архитектура и разделение ответственности

Приложение построено на чистом TypeScript (ES-модули, компиляция через `tsc` без бандлеров) и разделено на четыре независимых слоя:

- **`src/types/`** — описание контрактов внешнего API (`RawCountry`) и внутренней доменной модели (`Country`).
- **`src/api/`** — сетевой слой (`searchCountries`, `HttpError`). Отвечает только за формирование HTTP-запроса, обработку статусов ответа и маппинг сырых данных.
- **`src/utils/`** — чистые вспомогательные функции без привязки к DOM:
  - `debounce` — отложенный вызов обработчика ввода;
  - `mapCountryResponse` — преобразование ответа API в доменную модель с безопасными значениями по умолчанию;
  - `errorClassifier` — классификация исключений (`AbortError`, `TimeoutError`, `HttpError`, сетевые ошибки).
- **`src/core/`** — контроллер состояния поиска (`SearchController`), управляющий жизненным циклом запросов, кэшем, дедупликацией и историей в `localStorage`.
- **`src/ui/`** — слой представления (`AppView`, `CountryModal`, `createFooter`, `dom`). Вся разметка создаётся программно через DOM API (`document.createElement`, `textContent`, `replaceChildren`) без использования `innerHTML`.

## 2. Отмена запросов и защита от состояния гонки (Race Condition)

При быстром вводе текста пользователем возможна ситуация, когда более ранний сетевой запрос завершается позже последующего и перезаписывает актуальные результаты устаревшими данными. Для исключения гонок применена двухуровневая защита:

1. **Немедленная отмена (`AbortController`)**: при каждом новом вызове `SearchController.search()` или при очистке поля ввода предыдущий активный контроллер прерывается через `abortController.abort()`.
2. **Монотонный идентификатор запроса (`latestRequestId`)**: каждому запросу присваивается возрастающий номер `requestId`. После завершения `await fetch(...)` результат применяется к состоянию только в том случае, если `requestId === this.latestRequestId`.

## 3. Таймауты и семантика обработки ошибок

- **Композиция сигналов (`AbortSignal.any`)**: в `searchCountries` внешний `signal` (отмена по новому вводу) объединяется с сигналом таймаута `AbortSignal.timeout(timeoutMs)` с помощью `AbortSignal.any([signal, timeoutSignal])`.
- **Обработка `404 Not Found`**: API `countries.dev` возвращает статус `404`, если по запросу не найдено ни одной страны. В `searchCountries` этот статус интерпретируется как валидный пустой результат (`[]`), а не как ошибка сети или сервера.
- **Классификация исключений (`classifySearchError`)**:
  - `AbortError` — штатная отмена устаревшего запроса пользователем; игнорируется без показа ошибки.
  - `TimeoutError` — превышение времени ожидания ответа; отображается пользователю с кнопкой «Повторить».
  - `HttpError` — неуспешный HTTP-статус (кроме 404), сохраняющий код ответа; отображается с кнопкой «Повторить».
  - Сетевые сбои (`TypeError`) — отображаются как ошибка подключения с возможностью повтора.

---

## 4. Кэширование, дедупликация и история поиска

- **Кэширование результатов**: успешные ответы сохраняются в `Map<string, Country[]>` по нормализованному ключу `query.trim().toLowerCase()`. Повторные запросы с тем же ключом отдаются из памяти мгновенно без обращения к сети (при нажатии «Повторить» используется флаг `forceRefresh`, который обходит кэш). Ошибочные ответы в кэш не записываются.
- **Дедупликация параллельных запросов (`in-flight`)**: активные промисы хранятся в отдельной `Map<string, Promise<Country[]>>`. Если запрос с тем же нормализованным ключом уже выполняется, новый вызов переиспользует существующий промис вместо запуска дублирующего `fetch`.
- **История последних запросов**: до 5 последних уникальных поисковых запросов сохраняются в `localStorage` и отображаются в виде интерактивных чипов под строкой поиска.
