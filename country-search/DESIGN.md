# DESIGN.md — Архитектурные решения Country Search

## 1. Архитектура и разделение ответственности

Приложение построено на чистом TypeScript (ES-модули, компиляция через `tsc` без бандлеров) и разделено на независимые слои:

- **`src/types/`** — контракты внешнего API (`RawCountry`) и внутренней доменной модели (`Country`).
- **`src/api/`** — сетевой слой (`searchCountries`, `HttpError`). Отвечает за формирование HTTP-запроса, композицию сигналов отмены и таймаута, обработку HTTP-статусов и маппинг данных.
- **`src/utils/`** — чистые функции без привязки к DOM:
  - `debounce` — отложенный вызов обработчика ввода;
  - `mapCountryResponse` — преобразование сырого ответа API в доменную модель;
  - `errorClassifier` — классификация ошибок (`AbortError`, `TimeoutError`, `HttpError`, сетевые сбои).
- **`src/core/`** — контроллер состояния поиска (`SearchController`), управляющий отменой запросов, кэшем, дедупликацией и историей поиска.
- **`src/ui/`** — слой представления (`AppView`, `CountryModal`, `createFooter`, `dom`). Вся разметка строится программно через DOM API (`document.createElement`, `textContent`, `replaceChildren`) без использования `innerHTML`.

## 2. Обоснование механизма отмены и выбора задержки `debounce`

### Выбор задержки `debounce` (`350 мс`)

- Задержка **350 мс** выбрана как баланс между отзывчивостью интерфейса и снижением нагрузки на сеть:
  - При средней скорости печати (~180–250 символов/мин, интервал между нажатиями 200–300 мс) таймер сбрасывается на каждом символе, не отправляя промежуточные «мусорные» запросы на сервер при наборе слова целиком.
  - В то же время пауза в 350 мс воспринимается пользователем как мгновенная реакция после завершения ввода, без ощущения «подвисания» интерфейса.

### Механизм отмены (`AbortController` + `AbortSignal.any`) и защита от гонок

1. **Немедленная отмена при каждом изменении ввода**: при срабатывании события `input` (в `src/index.ts`) вызывается `controller.cancelActiveRequest()` **сразу**, не дожидаясь срабатывания нового таймера `debounce`. Это экономит трафик и гарантирует, что устаревший запрос прерывается в момент начала ввода нового текста или очистки поля.
2. **Монотонный идентификатор `latestRequestId`**: каждому поисковому запросу присваивается возрастающий номер `requestId`. Если ответ от устаревшего запроса всё же пришёл в момент переключения, проверка `requestId !== this.latestRequestId` отбрасывает его и не допускает перезаписи актуального состояния.
3. **Композиция сигналов таймаута (`AbortSignal.any`)**: в `searchCountries` внешний сигнал отмены объединяется с `AbortSignal.timeout(15000)` через `AbortSignal.any([signal, timeoutSignal])`, что позволяет в едином блоке `catch` разделять ручную отмену (`AbortError`) и истечение таймаута (`TimeoutError`).

## 3. Оценка сложности (Big O)

### `mapCountryResponse(raw: RawCountry): Country` — **$O(L + C)$** (или **$O(1)$** на одну страну в практических границах)

- Внутри `mapCountryResponse` выполняются:
  - чтение и нормализация скалярных полей (`name`, `capital`, `region`, `population`, `area`, `flag`) — **$O(1)$**;
  - проход по массиву языков `raw.languages.map(...)` длины $L$ — **$O(L)$**;
  - проход по массиву валют `raw.currencies.map(...)` длины $C$ — **$O(C)$**.
- Итоговая сложность преобразования одного объекта страны составляет **$O(L + C)$** по времени и **$O(L + C + B)$** по памяти (где $B$ — длина массива границ `borders`). Поскольку количество официальных языков, валют и сухопутных границ у любого государства ограничено небольшой константой ($L, C, B \le 20$), на практике преобразование одной страны выполняется за амортизированное **$O(1)$**, а преобразование списка из $N$ найденных стран — за **$O(N)$**.

### Кэширование и дедупликация в `SearchController` — **$O(1)$** в среднем

- Кэш результатов (`Map<string, Country[]>`) и реестр активных запросов (`Map<string, InFlightEntry>`) реализованы на базе стандартной хэш-таблицы `Map` с нормализованным строковым ключом `query.trim().toLowerCase()`.
- Поиск в кэше (`cache.has` / `cache.get`), запись в кэш (`cache.set`) и проверка активного `in-flight` запроса (`inFlight.get`) выполняются за **$O(1)$** в среднем по времени (с учётом вычисления хэша строки длины $K$ — $O(K)$) и занимают **$O(M)$** памяти, где $M$ — количество уникальных закэшированных запросов.
- История поиска в `localStorage` ограничена константой `MAX_HISTORY_ITEMS = 5`, поэтому фильтрация и обновление списка выполняются за **$O(1)$**.

## 4. Принципы чистого кода и места их применения

1. **Single Responsibility Principle (Принцип единственной ответственности)**:
   - `src/api/searchCountries.ts` занимается только сетевым взаимодействием и HTTP-статусами;
   - `src/utils/mapCountryResponse.ts` отвечает исключительно за трансформацию данных API в доменную модель;
   - `src/utils/errorClassifier.ts` изолирует логику классификации ошибок;
   - `src/core/searchController.ts` управляет только состоянием и кэшем, ничего не зная о DOM;
   - `src/ui/*` отвечает только за отображение состояния и подписку на события пользователя.
2. **Dependency Inversion / Dependency Injection (Инверсия зависимостей)**:
   - `SearchController` принимает функцию получения данных `fetcher: CountryFetcher` через конструктор вместо жёсткой привязки к глобальному `fetch`. Это позволило протестировать гонку запросов, отмену и кэширование детерминированными unit-тестами без сетевых вызовов.
3. **DRY (Don't Repeat Yourself)**:
   - Повторяющееся создание DOM-узлов и пар «метка — значение» вынесено в переиспользуемые хелперы `createElement` и `createInfoItem` в `src/ui/dom.ts`.
4. **Безопасность и явная обработка граничных случаев**:
   - Полный отказ от `innerHTML` в пользу `textContent` и DOM API исключает XSS-уязвимости при рендеринге данных из внешнего API;
   - HTTP `404` явно отделён от исключительных ошибок (`HttpError`), а `AbortError` отделён от `TimeoutError`.
