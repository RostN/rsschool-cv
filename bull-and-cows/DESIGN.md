# DESIGN.md — Архитектурное описание проекта "Быки и Коровы"

## 1. Структуры данных и алгоритмы

### Состояние игры и история попыток

Для хранения истории ходов и текущего состояния раунда используется иммутабельный массив объектов структуры `matchHistory: Array<{ guess: string; bulls: number; cows: number }>`. В соответствии с принципами функционального программирования (иммутабельность), обновление состояния при каждой новой попытке происходит без мутации исходного массива через оператор расширения (spread):
`matchHistory = [...matchHistory, newEntry]`
Это предотвращает непреднамеренные побочные эффекты и обеспечивает предсказуемость потока данных.

### Алгоритм подсчета результатов (evaluateGuess)

Функция `evaluateGuess` сравнивает скрытую строку `secret` и догадку пользователя `guess`. В соответствии с ТЗ, алгоритм полностью построен на декларативных методах перебора массивов (`reduce`) без использования императивных циклов `for/while` или ручных переменных-счетчиков:

1. Строки преобразуются в массивы символов в нижнем регистре.
2. Количество "быков" (совпадение символа и позиции) вычисляется через `.reduce()`, инкрементирующий аккумулятор при строгом равенстве элементов по одинаковому индексу.
3. Количество "коров" (символ угадан, но позиция не совпадает) рассчитывается аналогично через `.reduce()`, проверяя, что символ присутствует в секрете, но индекс текущего элемента не равен индексу совпадения.

### Алгоритм расчета вариантов (countPossibleSecrets)

Для вычисления количества возможных секретных чисел на основе длины `length` и размера алфавита `base` используется математическая формула размещений без повторений: P(n, k) = n! / (n-k)!.
Реализация выполнена в виде **чистой рекурсивной функции** с шагом:
`base * countPossibleSecrets(length - 1, base - 1)`
Для оптимизации производительности и исключения избыточных вычислений при изменении настроек интерфейса, функция обернута в паттерн **мемоизации** через кэширующий объект `memoCache`.

## 2. Временная сложность (Big O)

- **generateSecret(length, base)**: Сложность **O(B)**, где B — размер алфавита выбранной системы счисления (2, 8, 10 или 16). Алгоритм Fisher-Yates перемешивает фиксированный массив алфавита за линейное время от его длины, после чего выполняется срез `slice(0, length)`.
- **evaluateGuess(secret, guess)**: Сложность **O(L)**, где L — длина загаданного числа (`length`). Методы `.reduce()` осуществляют проход по массиву длины L, а метод `.includes()` на строке фиксированной длины также занимает константное время в пределах ограничений (длина от 2 до 6).
- **isValidGuess(guess, length, base)**: Сложность **O(L)**. Проверка `.every()` выполняет валидацию каждого из L символов, а создание `Set` для проверки уникальности занимает линейное время от длины строки.
- **countPossibleSecrets(length, base)**: Без мемоизации сложность составляет **O(L)**, так как глубина рекурсии равна длине числа `length`. С применением мемоизации при повторных вызовах сложность пападать до константной **O(1)**, поскольку результат мгновенно извлекается из кэша.

## 3. Принципы чистого кода (Clean Code)

В проекте применены следующие ключевые концепции написания чистого кода:

1. **DRY (Don't Repeat Yourself)**: Валидация символов вынесена в единую каррированную фабрику `createDigitValidator`, которая повторно используется как для валидации всей строки при отправке формы (`isValidGuess`), так и для фильтрации ввода букв пользователем в реальном времени на событии `input`.
2. **Принцип единственной ответственности (SRP)**: Модуль `src/game.ts` содержит исключительно чистые вычислительные функции игровой логики и полностью изолирован от окружения. Он ничего не знает о существовании DOM, браузера или интерфейса, что делает его на 100% тестируемым.
3. **KISS (Keep It Simple, Stupid)**: Отказ от избыточных классов, сложных архитектурных паттернов ООП или сторонних библиотек (вроде lodash) в пользу лаконичных встроенных методов прототипа `Array`.
