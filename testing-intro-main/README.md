# Testing Intro: Catalog & Cart

## Навыки

`JavaScript` `Jest` `unit tests` `TDD` `coverage` `e-commerce`

## Описание

В этой задаче вы работаете с мини-магазином из двух страниц: **каталогом** и **корзиной**. Интерфейс нужен для контекста: тестировать DOM, браузер или обработчики событий не требуется. Все тесты проверяют небольшие функции с бизнес-логикой.

Цены в проекте хранятся в копейках: например, `49900` означает 499 ₽. Это помогает не сталкиваться с ошибками округления дробных чисел.

## Материалы для изучения

- [Getting Started · Jest](https://jestjs.io/docs/getting-started) — установка и запуск тестов;
- [Using Matchers · Jest](https://jestjs.io/docs/using-matchers) — основные проверки через `expect`;
- [Code Coverage · Jest](https://jestjs.io/docs/cli#--coverageboolean) — отчёт о покрытии.

## Начало работы

1. Сделайте **fork** этого репозитория к себе на GitHub.
2. Склонируйте свой форк, перейдите в папку проекта и создайте рабочую ветку от `main`:

   ```bash
   git clone https://github.com/<ваш-github-логин>/testing-intro.git
   cd testing-intro
   git checkout -b testing-intro
   ```

3. Установите зависимости:

   ```bash
   npm install
   ```

4. Используйте команды по ходу работы:

   | Команда | Назначение |
   | --- | --- |
   | `npm test` | запустить все тесты |
   | `npm run test:catalog` | запустить только тесты первой части |
   | `npm run test:cart` | запустить готовые тесты корзины |
   | `npm run test:coverage` | создать отчёт coverage; затем открыть `coverage/lcov-report/index.html` |

Каталог можно открыть в браузере через `index.html`, а корзину — через `cart.html`.

## Часть 1. Тесты для готового каталога

Файл `src/catalog.js` уже содержит пять работающих функций. Для `getAvailableProducts` есть полный пример тестов в `tests/catalog/getAvailableProducts.test.js`.

Напишите тесты для остальных функций:

- `filterByCategory`;
- `searchProducts`;
- `sortProductsByPrice`;
- `getProductById`.

Используйте Jest. Для запуска только этой части:

```bash
npm run test:catalog
```

Создайте по одному файлу тестов для каждой функции: `filterByCategory.test.js`, `searchProducts.test.js`, `sortProductsByPrice.test.js`, `getProductById.test.js`. Каждый пункт ниже — отдельный Jest-кейс. Выполните все **36 обязательных тестов**.

## Часть 2. Корзина через тесты

Во второй части откройте `tests/cart/cart.test.js`. В нём уже записаны правила работы корзины, а в `src/cart.js` находятся заглушки. Сначала запустите тесты — они должны быть красными:

```bash
npm run test:cart
```

Реализуйте функции в `src/cart.js`, не изменяя тесты:

- `addToCart` — добавить товар или увеличить его количество;
- `changeQuantity` — изменить количество товара;
- `removeFromCart` — удалить товар;
- `calculateCartSubtotal` — посчитать стоимость товаров;
- `calculateOrderTotal` — посчитать скидку, доставку и итог.

Правила заказа описаны тестами: промокод `SAVE10` даёт скидку 10% при сумме товаров от 20 000 копеек, а доставка стоит 30 000 копеек при сумме меньше 50 000 копеек. Количество товара должно быть положительным и не может превышать остаток на складе.

Когда функции будут реализованы, страница корзины начнёт работать. Так тесты останутся главным источником требований, а интерфейс позволит увидеть результат руками.

## Coverage

В проекте настроен отчёт о покрытии:

```bash
npm run test:coverage
```

После запуска откройте `coverage/lcov-report/index.html`. Покрытие не влияет на оценку и не имеет минимального порога: его цель — познакомить с инструментом и показать, какие строки были выполнены тестами. В отчёт входят только файлы с бизнес-логикой, а не браузерный интерфейс.

## Требования

- Используйте Jest.
- В первой части меняйте только тесты в `tests/catalog/`.
- Во второй части меняйте только `src/cart.js`.
- Не меняйте исходные данные, готовый пример теста, тесты корзины, настройки Jest и браузерный интерфейс.
- Не используйте сеть, таймеры, сторонние библиотеки и DOM-тесты.
- Все тесты должны проходить командой `npm test`.

## Cross-check

После дедлайна, на следующей неделе, RS App сформирует пары для проверки. Каждый студент проверяет назначенные ему работы в разделе **Cross-Check: Review**.

### Как проверять работу

1. Откройте Pull Request и убедитесь, что он направлен из рабочей ветки в `main` **личного** форка и не замержен.
2. Во вкладке **Files changed** проверьте, что студент не менял `src/catalog.js`, `src/data/products.js`, готовый пример теста, `tests/cart/cart.test.js`, `package.json`, настройки Jest и файлы интерфейса.
3. Склонируйте репозиторий, выполните `npm install`, затем `npm test` и `npm run test:coverage`.
4. Проверьте тесты каталога: для каждой из четырёх функций должны быть как минимум три сценария, по три конкретных кейса в каждом.
5. Проверьте, что реализация корзины соответствует готовым тестам, а все тесты проходят.
6. Поставьте оценку по критериям и оставьте комментарий. Для каждого неполного пункта объясните, что именно отсутствует или работает неверно.

## Критерии оценки

**Максимальный балл: 100.**

### Часть 1. Тесты каталога (40)

По **10 баллов** за каждую функцию: `filterByCategory`, `searchProducts`, `sortProductsByPrice`, `getProductById`.

Функция получает 10 баллов, если для неё выполнены все девять обязательных тестов из таблицы выше и каждый проверяет указанные входные данные и результат.

### Часть 2. Корзина по готовым тестам (40)

- `addToCart`: новый товар, объединение одинаковых товаров, проверка количества и остатка — **10**;
- `changeQuantity`: изменение количества, проверка границ, отсутствующий товар — **10**;
- `removeFromCart` — **6**;
- `calculateCartSubtotal` — **6**;
- `calculateOrderTotal`: скидка, доставка и итоговая сумма — **8**.

Все готовые тесты должны проходить.

### Оформление и сдача (20)

- работа выполнена в личном форке, в отдельной ветке; история коммитов соответствует конвенции — **5**;
- Pull Request открыт в `main` личного форка, не замержен и оформлен по схеме — **5**;
- в PR есть скриншот успешного `npm test` — **5**;
- в PR есть скриншот HTML-отчёта coverage — **5**.

### Штрафы

- Изменены `src/catalog.js`, `src/data/products.js` **−40**.
- Изменены `tests/cart/cart.test.js`, `package.json` или настройки Jest **−40**.
